# 10. 에셋 교체 가이드 (디자이너)

> 이 문서는 **디자이너 관점**이다. prefab 구조 설계·직렬화·빌드 파이프라인은 개발자 영역이며 `13_부록_개발자_구축영역.md` 에 있다. 여기서는 **이미지·사운드를 안전하게 교체하는 법**만 다룬다.

---

## 1. 핵심 원칙 (외우기)

1. **원본은 `raw-assets/` 에서만 작업**한다. `public/assets/` 는 빌드 결과라 **직접 건드리지 않는다.**
2. 이미지는 raw PNG 를 코드에서 바로 쓰지 않는다. **시트로 묶어 빌드한 뒤** atlas key 로 쓴다.
3. 파일 **이름을 마음대로 바꾸지 않는다**(코드/시트가 참조). 교체는 "같은 이름으로 갈아끼우기"가 가장 안전하다.

---

## 2. 폴더 위치 (어디에 넣나)

```text
raw-assets/game/
├─ images/          ← 이미지 원본 (여기서 작업)
│  ├─ bg/           배경
│  ├─ common/       공통 아이콘·프레임
│  ├─ betting/      베팅 UI
│  ├─ play/         플레이 영역 오브젝트
│  └─ popup/        팝업
│  └─ bg.json / common.json / betting.json / <game>.json   ← 역할별 시트
├─ sound/           ← 사운드 원본 (여기서 작업)
├─ prefabs/         (개발자 영역)
└─ scenes/          (개발자 영역)

public/assets/game/…   ← build:assets 결과. 직접 수정 금지
```

---

## 3. 이미지 교체 흐름

```text
1. 새 PNG 를 준비한다 (기존과 같은 용도/비율 권장).
2. raw-assets/game/images/<역할>/ 에 넣는다.
   - 가장 안전: 기존 파일과 같은 이름으로 덮어쓰기
   - 새 파일이면 해당 역할 시트(json)에 등록되도록 개발자와 규칙 확인
3. 에셋 빌드 실행:  npm run build:assets   (개발 중엔 build:assets:dev)
4. public/assets/game/images/<sheet>-<hash>@1x.json 이 생성됨(자동)
5. dev 서버에서 화면 확인
```

- 파일명은 kebab-case: `img-background-main.png`, `btn-play-normal.png`, `icon-coin.png`, `panel-result-frame.png`.
- 새 이미지의 **크기·비율을 기존과 맞추면** 레이아웃이 안 흔들린다.

### 3.1 절대 금지
- ⛔ `public/assets/game/images/{bg,common,betting,play,popup}/` 에 원본 PNG 직접 넣기
- ⛔ `assets/`, `app-assets/` 같은 새 폴더를 빌드 결과 기준으로 만들기
- ⛔ 이미지 폴더에 prefab 섞기

---

## 4. 사운드 교체 흐름

```text
1. 새 사운드(.wav 우선, .mp3 가능)를 raw-assets/game/sound/ 에 넣는다.
2. 논리 이름(파일 basename)이 코드가 부르는 이름과 1:1 이어야 한다.
   예) button-click.wav / sfx-win.wav / bgm_02.wav
3. 에셋 빌드 → 화면에서 재생 확인
```

- 볼륨·타이밍·ducking 규칙은 `07_사운드_가이드.md`.
- 없는 사운드는 코드가 조용히 넘어가고 경고 1회만 남긴다(→ 파일명 확인).

---

## 5. 색·폰트는 "에셋"이 아니라 "토큰"이다

이미지/사운드는 파일 교체지만, **색·폰트 크기는 prefab marker 값**을 바꾸는 것이다(파일 교체 아님).

| 바꾸고 싶은 것 | 방법 |
| --- | --- |
| 배경/버튼/아이콘 그림 | raw-assets 이미지 교체(위 3장) |
| 색상 | prefab `PaletteMarkers` 값 (SceneMaker/개발자) → `04` |
| 폰트 크기·색 | prefab `TypeMarkers` 값 → `05` |
| 폰트 자체(패밀리) | 폰트 에셋 + 코드 진입점(개발자 확인) |

---

## 6. 없는 에셋(placeholder) 처리

- 아직 에셋이 없으면 코드가 **Graphics fallback**(도형)으로 임시로 그린다.
- 임시 상태라는 걸 `확인 필요 항목`에 남겨 두고, 실제 에셋이 준비되면 위 흐름으로 교체한다.

---

## 7. 교체 후 체크

- [ ] `raw-assets/` 에서만 작업했는가? (`public/assets` 직접 수정 0)
- [ ] 파일명이 기존 참조와 일치하는가? (이름 변경 시 개발자 확인)
- [ ] 새 이미지 크기/비율이 레이아웃을 흔들지 않는가?
- [ ] 에셋 빌드 후 화면/사운드가 정상인가?
- [ ] 사운드 논리 이름이 코드 호출 이름과 1:1 인가?

---

## 8. AI에게 에셋 작업 시킬 때 (복붙용)

```text
이미지/사운드 교체만 한다. raw-assets/game/ 아래에서만 작업하고 public/assets/ 는 건드리지 마라.
파일 이름은 기존 참조를 유지한다(이름을 바꿔야 하면 실행하지 말고 알려라).
색·폰트 크기는 파일이 아니라 prefab marker(PaletteMarkers/TypeMarkers) 값이다. 코드에 하드코딩하지 마라.
에셋이 없으면 Graphics fallback 을 쓰고 "확인 필요"로 남겨라.
```
