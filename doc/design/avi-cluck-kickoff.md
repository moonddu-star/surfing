작성일: 2026-09-22. 상태: 문서 검토 완료, 템플릿·레이아웃·UI 이미지 수령 대기. 게임 구현 및 실행 검증은 아직 시작하지 않았다.

## 기준 문서와 우선순위

1. [파이프라인 SKILL](../pixibrown-blitzcrown-pipeline/SKILL.md) 및 연결된 제작 규칙
2. [Avi-Cluck GDD](Avi-Cluck_GDD.md)
3. 디자인 공통 가이드와 [버튼 상태 가이드](Button_State_Sequence_Guide.md): 위 두 기준과 충돌하지 않는 범위

사용자가 지칭한 skills.md의 실제 파일은 `pixibrown-blitzcrown-pipeline/SKILL.md`다. 이 문서는 구현을 위한 작업 메모이며 원본 규칙을 대체하지 않는다.

`00_공통가이드_인덱스.md`에는 Massive Mines, `03`·`09` 등에는 다른 장르의 화면과 오토 UI 예시가 있다. 해당 게임명·레이아웃·규칙을 Avi-Cluck에 복사하지 않는다. 원본 문서는 수정하지 않았다.

## 첫 구현 범위

템플릿과 첫 화면 자료를 받은 뒤, 제공 이미지가 있는 메인 구좌 UI부터 작은 단위로 진행한다. 이는 진행 순서이며 최종 제품의 메인 2구좌 요구를 줄이는 것이 아니다.

1. 실제 템플릿의 지침, 의존성, GameMain·Sequence·LocalServer 계약과 기본 프리팹을 확인한다.
2. 제공 PC·모바일 레이아웃에서 첫 구좌의 위치·크기를 측정해 `layout.md`에 기록한다. 자료 수령 전에는 좌표를 정하지 않는다.
3. 제공 PNG를 kebab-case로 `raw-assets/game/images/{atlas}/`에 복사하고 prefab에 연결한다. 이미지가 없는 노드는 만들지 않는다.
4. Container 루트에 Button/InputField/State 컴포넌트를 붙이고 하위 Sprite를 배치한다. 목록에는 LayoutGroup/ScrollRect를 사용한다.
5. 첫 구좌의 금액 입력·예약·취소와 필요한 클라이언트/로컬 서버 연결을 구현한다. 확정된 프로토콜을 사용하며 구좌 식별자나 요청 필드 이름을 추측하지 않는다.
6. 에셋 변경 후 `npm run build:assets:dev`를 실행한 뒤 SceneMaker와 개발 서버에서 확인한다.
7. 첫 구좌 확인 후 두 번째 메인 구좌, 사이드 줄, 스테이지·출목·베팅 리스트 순으로 제공 자료에 맞춰 확장한다.

## 확정된 핵심 요구사항

아래 값은 구현 시 원본 GDD와 다시 대조하며 서버 설정으로 연결한다.

| 항목 | GDD 기준 |
| --- | --- |
| 구좌 | 메인 2개 + 사이드 1개. 금액·예약·취소·정산은 독립 |
| 기본 RTP | Ver 2 메인·사이드 96%, 즉시 크래시 확률 0.04, 사이드 지급 배율 24 |
| 금액 | 구좌별 최소 0.1, 최대 1000, 기본 1, 증감 1. 메인만 1/2/5/10 퀵 프리셋 |
| 라운드 | 베팅 대기 6000ms, 일반 결과 2600ms, 즉시 크래시 결과 6950ms |
| 배율 | exp(0.085 × 경과초), 상한 5000x에서 잔여 라이브 메인 강제 정산 |
| 즉시 크래시 | 독립 분기로 결정. 일반 분기는 최소 1.01x로 제한하여 반올림·버림으로 즉시 크래시가 추가되지 않게 함 |
| 캐시아웃 | 서버 수신 시점·서버 배율 기준, 구좌당 한 번만 지급 |
| 사이드 | 이륙 시 결과 확정·지급, 결과 홀드 1600ms. 홀드 중 라운드 종료 시 다음 대기에서 초기화 |
| 메인 오토 | 켠 뒤 다음 대기 진입부터 예약. 두 메인 오토는 구좌 1 우선 |
| 사이드 오토 | 대기 중 켜면 현재 라운드에 즉시 예약. 상승·결과 중 켜면 다음 대기부터 |

| 모바일 | 두 번째 구좌 기본 접힘, 예약·라이브일 때 접기 금지 |

| 재접속 | 서버 라운드·잔고·이력 복원 완료까지 입력 차단 |

## 구현 전에 확인할 계약·기획

초기 착수에 필요한 것은 템플릿 경로와 첫 화면 자료다. 아래 항목은 관련 기능을 구현할 때 확정하며 임시값으로 채우지 않는다.

- **잔고 부족 시 오토:** GDD §5.1·§5.2는 토글 ON 유지·다음 라운드 재시도, §9의 1393 설명은 오토 중단으로 되어 있다. 같은 GDD 내 충돌이므로 확정이 필요하다.
- **서버 계약:** 공유 라운드 알림, 구좌 식별, 예약·취소·캐시아웃, 중복 요청 방지, 서버 시간·잔액 통지의 실제 이벤트와 payload가 없다. 파이프라인 예시의 단일 REQ_BET 응답만으로 계약을 단정하지 않는다.
- **동시 판정 경계:** 자동 정산 목표와 크래시 포인트가 정확히 같을 때 처리 순서를 확인한다.
- **지급 정밀도:** GDD §6.2의 크래시 포인트 버림, §6.3의 표시 배율 버림 및 지급 계산용 원배율을 구분하고 서버 정밀도를 확인한다.
- **확률 경계:** §6.2의 1.01x 하한 클램프와 일반 생존확률 식은 1.00~1.01 경계에서 따로 검토한다. 난수 0 처리와 상한 도달도 검증한다.
- **TBD:** 통화별 slide, max_exposure와 적용 단위, 자동 정산 하한, 반복 횟수·손익 조건 도입 여부, 베팅 리스트 행 수·마스킹 정책, 사이드 Free Bet 적용, 튜토리얼 상세, 사운드, 자동 정산 없는 메인 베팅의 연결 단절 처리.

## 구현 후 검증할 사항

- SceneMaker에서 게임 UI가 prefab만으로 보이며 누락된 참조가 없는가.
- 예약·취소 연타에도 한 구좌가 중복 차감·환급되지 않는가.
- 한 구좌의 잠금·캐시아웃이 다른 구좌를 변경하지 않는가.
- 즉시 크래시는 상승 없이 사이드 지급·메인 손실로 끝나는가.
- 사이드 홀드와 다음 라운드 예약이 빠른 크래시에서도 어긋나지 않는가.
- 재접속 시 서버 상태 복원 전 입력이 차단되는가.
- 에셋 빌드 후 PC·모바일 화면을 제공 레이아웃과 비교했는가.

현재는 문서 점검만 수행했다. 위 실행 검증은 템플릿 확보 후 해당 구현과 함께 수행한다.
