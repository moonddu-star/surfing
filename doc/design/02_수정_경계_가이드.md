# 02. 수정 경계 가이드 (안전 / 확인 필요 / 금지)

이 가이드 묶음에서 **가장 먼저, 가장 자주** 보는 문서다. 개발자가 구축한 prefab/환경 위에서 디자이너가 바이브 코딩할 때 **무엇을 바꿔도 되고, 무엇을 건드리면 깨지는지**를 정한다.

기호: ✅ 안전(디자이너가 자유롭게) / ⚠️ 확인 필요(개발자 문의) / ⛔ 금지(하지 않는다)

---

## 1. 한 장 요약표

| 대상 | 판정 | 이유 |
| --- | --- | --- |
| 색 값 (prefab marker) | ✅ | 색의 정본은 marker. 값만 바꾸면 안전 |
| 폰트 크기·색 (prefab marker) | ✅ | 타이포 정본도 marker |
| 배경·아이콘·버튼 이미지 교체 | ✅ | raw-assets 규칙만 지키면 안전 |
| 문구·라벨 텍스트 | ✅ | (현지화 키 규칙 지키면) |
| 연출(이펙트) 강도·타이밍 | ✅ | 가림 규칙(08) 안에서 |
| 사운드 연결·볼륨·타이밍 | ✅ | 07 규칙 안에서 |
| 슬라이더 범위·프리셋 표시값 | ✅ | 서버 한도 안에서 |
| 패널·라벨 **위치** 미세 조정 | ⚠️ | prefab 값이면 안전, 코드 하드코딩이면 확인 |
| 폰트 굵기·자간·줄간격 | ⚠️ | prefab 이 못 담아 코드가 가짐 → 진입점만 |
| 노드 **이름** 변경 | ⛔ | 코드가 이름/배선으로 찾음 → 조용히 깨짐 |
| 노드 삭제·이동, 레이어 구조 변경 | ⛔ | @Serialize 배선 끊김 |
| 확률·배당·payload·베팅 한도 | ⛔ | 서버 계약값 |
| `pixibrown/`, `src/common/`, `src/network/` | ⛔ | 프레임워크·공통 계층 |
| 빌드 설정(vite/tsconfig/terser) | ⛔ | 로딩·직렬화가 깨짐 |
| `public/assets/` 직접 수정 | ⛔ | 빌드 결과물. 원본은 raw-assets |

---

## 2. ✅ 안전하게 바꿔도 되는 것

- **배경 이미지 교체**
- **버튼 이미지 교체**
- **아이콘 교체**
- **색상 변경** (prefab `PaletteMarkers` 값)
- **폰트 크기 조정** (prefab `TypeMarkers` 값)
- **패널/라벨 위치 조정** (prefab 좌표 값일 때)
- **팝업 비주얼 변경**
- **placeholder 에셋 교체**
- **spritesheet 에 들어갈 개별 PNG 교체**
- **연출 강도·타이밍** (강도 1~10 범위, 가림 규칙 준수)
- **사운드 볼륨·간격·ducking** 값
- **문구·라벨** (현지화 키 규칙 준수)
- **슬라이더/프리셋 표시 범위** (서버 한도 이내)

> 원칙: "보이는 것·들리는 것·느껴지는 것"의 값 조정은 대체로 안전하다. 단, **구조가 아니라 값**을 바꾼다.

---

## 3. ⚠️ 개발자 확인이 필요한 것

- 노드 **이름** 변경
- `componentName` 변경
- 화면 골격 레이어(예: `LayerGame`, `LayerPlayDynamic`) 삭제·이동
- 메인 prefab / GameRoot / Shell 컨테이너 구조·해상도 변경
- PlayArea / Selection / Betting / Hud / Popup 같은 역할 패널 제거
- 화면 전체 레이아웃 재설계
- 버튼 구조 변경
- 동적 Renderer 가 사용하는 부모 Layer 변경
- payload 구조 변경
- 확률/배율/보상 계산 변경
- spritesheet 시트 이름 변경, manifest key 변경
- 폰트 **굵기·자간·줄간격**(prefab 이 못 담는 값 — 코드 진입점을 통해서만)

> 위 항목은 "값"이 아니라 "구조/계약"을 바꾸는 것이라, 잘못 건드리면 화면이 조용히 깨지거나 서버와 어긋난다.

---

## 4. ⛔ 절대 건드리지 않는 것

- `pixibrown/` 내부 소스 (프레임워크 — 읽기만)
- `src/common/`, `src/network/`, `src/intro/` (공통 계층 — 상속으로만 확장, 디자이너는 손대지 않음)
- 네트워크/서버 어댑터/wire 포맷
- 상태 관리 구조
- 빌드 설정: `vite.config.ts`, `tsconfig.json`, `terserOptions`(특히 `mangle.properties` 켜기 금지)
- `@RegisterComponent('...')` 문자열 / prefab `componentName` (바꾸면 로딩이 깨짐)
- `public/assets/` 아래 원본 직접 생성/수정
- 확률·배당·최대당첨·베팅 한도 같은 서버 계약 값의 임의 생성

---

## 5. 왜 노드 이름/배선을 건드리면 안 되나 (원리)

- 코드는 prefab 노드를 **`@Serialize` 배선** 또는 **이름 조회**로 찾는다.
- 노드 이름을 바꾸거나 지우면, 코드가 그 노드를 못 찾아 **컴파일 에러가 아니라 "런타임에 그 부분이 안 그려지는"** 형태로 조용히 깨진다.
- 배선이 끊기면 개발 모드에서는 즉시 에러를 던지고, 운영에서는 그 섹션만 비게 만든다(어긋난 화면이 정상처럼 보이는 것을 막는 장치).
- 그래서 **구조는 개발자, 값은 디자이너**로 나눈다.

---

## 6. 왜 색/폰트/좌표를 코드에 쓰면 안 되나 (원리)

- 색·폰트 크기·좌표의 **정본은 prefab 의 marker 노드**다. 런타임 코드는 이 값을 읽어서 그릴 뿐이다.
- 코드에 값을 직접 쓰면, SceneMaker 에서 디자이너가 바꾼 값이 **조용히 무효화**된다(코드가 이겨버림).
- 그래서 값 변경은 반드시 marker(또는 SceneMaker/개발자)를 통해서 한다. (→ `04`, `05`, `10`)

### 6-1. Figma 는 정본이 아닌가? — 기준의 3층 구분

`Figma = Source of Truth` 와 `prefab marker = 값의 정본` 은 충돌이 아니라 **역할이 다르다.**

| 층 | 무엇의 기준 | 하는 일 |
| --- | --- | --- |
| **Figma** | 디자인 의도("어떻게 보여야 하는가") | 색·크기·여백을 **결정** |
| **Prefab marker** | 그 값이 실제로 들어가는 자리(값의 정본) | 결정된 값을 **적용/보관** |
| **MD 가이드** | 제작 규칙("무엇을/어떻게 해도 되는가") | 가림·강도·한도 등 **한계** |

> 흐름: **Figma에서 값을 정한다 → 그 값을 코드가 아니라 prefab marker(SceneMaker/개발자)에 넣는다.**
> ⛔ 흔한 실수: "Figma에 이 색이니까" 하고 **코드에 색을 직접 박기**. Figma 값이라도 marker 를 통해 적용한다.

## 7. AI 바이브 코딩 안전 지시문 (복붙용)

```text
이 프로젝트는 개발자가 prefab·씬·네트워크·상태·빌드 환경을 이미 구축해 둔 상태다.
너는 그 환경 위에서 화면 연출/표시/값만 조정한다.

건드리지 마라:
- prefab 노드 이름, @Serialize 배선, @RegisterComponent 문자열
- src/common/, src/network/, pixibrown/, 빌드 설정(vite/tsconfig/terser)
- 네트워크/서버 어댑터/wire 포맷, 상태 관리 구조
- 확률·배당·payload·베팅 한도 등 서버 계약 값
- public/assets/ 아래 원본 파일

해도 되는 것:
- src/game/ 안의 연출/표시 로직
- prefab marker(색·폰트 크기) 값, 이미지/사운드 교체, 문구, 연출 강도·타이밍, 슬라이더 범위

규칙:
- 색·폰트 크기·좌표는 prefab 이 정본이다. 코드에 하드코딩하지 마라.
- 이펙트/사운드는 1~10 강도로 표기하고 CTA·결과 금액·핵심 오브젝트를 가리지 마라.
- 노드를 지우거나 이름을 바꿔야 할 것 같으면 실행하지 말고 "개발자 확인 필요"로 보고해라.
- 애매한 값(확률·한도·경로)은 임의로 만들지 말고 "확인 필요"로 남겨라.
- 작업 후: 바꾼 것 목록 + 개발자 확인 필요 항목을 정리해라.
```

## 8. 작업 전 자가 점검 3문장

1. 내가 바꾸려는 게 **"값"인가 "구조"인가?** (값=대체로 안전, 구조=확인 필요/금지)
2. 이 값의 **정본이 prefab marker 인가?** 그렇다면 코드가 아니라 marker 를 바꾼다.
3. 노드 **이름·배선·서버 계약**에 손이 가는가? 그렇다면 멈추고 개발자에게 확인한다.
