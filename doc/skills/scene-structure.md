# 씬 정리 원칙

POC 변환과 기획서 제작 **둘 다** 이 문서를 따른다. 위젯 JSON은 [scene.md](scene.md). 아이템 prefab은 [pattern-prefab.md](pattern-prefab.md).

이 문서의 트리·이름(`BottomUI`, `AutoSettings`, `BtnBet`, `InputField` 설정창 등)은 **한 게임의 예시**다. 대상 게임의 Contents / HUD / 팝업 내부를 그대로 복제하지 않는다. 게임마다 구성은 달라진다.

파악할 것은 **나누고 묶는 방식**이다.

목표는 SceneMaker에서 **고치기 쉬운 트리**다. POC/레이아웃과 같은 화면이어도, 좌표를 평평하게 옮긴 트리는 실패다.

## 위젯 선택

**이미 있는 UI**는 작업자가 바꾸라고 하지 않으면 그대로 둔다. 키패드·칩·전용 피커를 `InputField`로 교체하지 않는다.

**새로 만드는 입력 UI:**

- 기획서에 형태가 있으면 그 형태
- 없으면 기본은 `InputField` ([scene.md](scene.md) 쿡북)

쿡북은 붙이는 방법이다. 다른 게임 prefab의 위젯을 대상 게임에 씌우지 않는다.

## 나누기

먼저 **역할이 다른 층**을 가른다. 자식 이름·개수는 게임마다 다르다.

- 창 여백 배경과 논리 해상도 안 게임 배경은 다른 노드
- 플레이 영역(보드, 릴, 테이블 …)과 항상 보이는 HUD와 모달은 다른 부모
- intro 시스템(SceneManager, PopupManager, 공용 팝업)은 게임 씬에 복제하지 않는다

템플릿이 주는 큰 껍질만 공통이다.

```
Root
├── (여백 배경) [FitToScreen]
├── Main [GameMain 서브클래스]
│   ├── (게임 배경)
│   ├── Contents          # 본편. 안은 게임마다 다름
│   └── (HUD)             # 이름이 BottomUI가 아니어도 됨
└── Popup                 # 게임 전용 모달만
```

Contents 안에 보드/페이테이블/헤더가 있어야 하는 것은 아니다. 그 게임에 있는 본편만 둔다.

## 묶기

같이 움직이거나 같이 켜지고 꺼지는 것을 **한 부모**로 둔다.

- 라벨+값+게이지처럼 한 덩어리인 표시 → 한 컨테이너
- 같은 자리에 갈아끼우는 상태(일반 베팅 / 오토 / 보너스 HUD 등)가 있으면, 상태마다 **그 상태에서 보이는 컨트롤을 가진 자식**을 겹친다. 공유되는 것만 밖에 둔다. 대기에서 보일 자식만 `enable: true`
- 바깥을 눌러 닫는 시트는 작은 패널만 두지 않고, 히트를 받는 딤/콜라이더와 본문을 나눈다
- 반복되는 칸·행은 씬에 복제하지 않고 아이템 prefab + 호스트(`Grid` 등) + 런타임 `clone()`. SceneMaker에서 호스트가 비어 보이는 것은 정상

도메인 컴포넌트는 **그 기능의 루트**에만 붙인다. 칸마다 컨트롤러를 붙이지 않는다. 부모는 원형 에셋 + 호스트만 `@Serialize`. `@RegisterComponent`는 파일당 하나.

이름은 동작·역할을 따른다. 카피 문구를 노드 이름에 넣지 않는다. 같은 역할 호스트는 같은 이름을 쓴다.

## 나열은 좌표로 쌓지 않는다

POC/레이아웃 숫자는 **앵커의 힌트**다. 흐름으로 늘어나는 UI를 `pos.y`로 쌓지 않는다.

| 이런 배치일 때 | 좌표 나열 대신 |
|----------------|----------------|
| 세로로 이어지는 섹션·행 | `VerticalLayoutGroup` (`fitToContents`, spacing) |
| 가로로 이어지는 칩·아이콘 줄 | `HorizontalLayoutGroup` 또는 `Grid` |
| 화면보다 긴 문서·설정 목록 | `ScrollRect` + Viewport `Mask` + Content 레이아웃 그룹 |
| 글자 길이에 프레임이 따라감 | LayoutGroup + Frame `followParentSize` (9-slice) |
| 패널 안쪽 여백 | `followParentSize` + `fitPadding` |

레이아웃 그룹이 못 잡는 자리(로고, 고정 앵커 버튼)에만 `transform.position`을 쓴다.

엔진 위젯 **트리**는 해당 쿡북을 연다. 새로 붙일 위젯이 그 종류일 때.

## 그린필드(기획서)

레이아웃 PNG를 자로 재서 절대좌표 트리를 만들지 않는다. 이 저장소의 HUD를 다른 게임에 복사하지 않는다.

1. 역할 층으로 나눈다
2. 같이 켜지는 것끼리 묶는다
3. 나열·반복 칸은 위 규칙
4. 새 입력은 기획서 형태. 없으면 `InputField`. 이미 있는 UI는 요청 없이 바꾸지 않는다
5. 남은 앵커만 `layout.md`에 적는다

레이아웃에 없는 배치는 추측하지 않고 묻는다.
