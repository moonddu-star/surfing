# 03. UI/UX 화면 구조 가이드

베팅형 게임의 세로 화면 레이아웃 순서, 패널 구성, 상호작용 규칙을 담는다. CRASH·MINE·WHEEL 등 새 게임도 이 골격을 재사용하고 중앙 PlayArea만 게임에 맞게 바꾼다.

> **디자이너 관점:** 화면 골격(패널·레이어)은 개발자가 prefab 으로 잡아 준다. 디자이너는 그 위에서 **값·상태·연출**을 조정한다. 노드를 지우거나 이름을 바꾸는 구조 변경은 ⚠️ 개발자 확인(→ `02`).

---

## 1. 화면 기본 규격

- 기준 해상도: **1080 × 1920** (세로, 9:16 고정)
- 콘텐츠 폭: **1040px**, 좌우 안전 여백: **20px** (콘텐츠 레일 `x:20, width:1040`)
- 전체 UI는 **하나의 고정 프레임**으로 확대/축소한다(개별 요소를 뷰포트별로 재배치하지 않음).
- 레터박스 영역은 검정 또는 배경보다 어두운 색으로 채운다.

```ts
const DESIGN_WIDTH = 1080;
const DESIGN_HEIGHT = 1920;
const scale = Math.min(window.innerWidth / DESIGN_WIDTH, window.innerHeight / DESIGN_HEIGHT);
```

## 2. 표준 세로 레이아웃 순서 (위 → 아래)

두 게임(Dice·Limbo)의 공통 골격이다. 새 게임은 **4번 PlayArea 만 교체**하고 나머지는 유지한다.

```text
┌──────────────────────────── 1080 × 1920 ────────────────────────────┐
│ 1. Header          (1040 × 50)   게임명 + 메뉴(햄버거) 버튼          │
│ 2. History row                    최근 결과 pill 나열                 │
│ 3. 중앙 결과 표시                 큰 결과 숫자 / 카운터(성공 · 목표)  │
│ 4. PlayArea (게임별)              ★ 핵심 플레이 영역(보드/캔버스)     │
│ 5. Side Betting 배너 (1040 × 70)  사이드 베팅 진입(옵션)             │
│ 6. 메인 값 입력 (2~3열)           예) Multiplier / Chance / Mode      │
│ 7. 값별 슬라이더 패널             입력과 연동되는 슬라이더            │
│ 8. 개수/모드 프리셋 + 슬라이더    예) [1][2][10][50][100] + 슬라이더  │
│ 9. Bet Amount 패널 (1040 × 226)   금액 입력 + 퀵버튼(½ · 2× · Max)   │
│ 10. Turbo 토글 + Balance Meta                                        │
│ 11. Primary CTA (BET, 1040 × 110) 풀와이드 (오토 중 STOP 전환)       │
│ 12. Footer Balance                                                   │
└──────────────────────────────────────────────────────────────────────┘
```

- 좌표·크기 상세는 `06_사이즈_레이아웃_가이드.md`, 색은 `04_컬러_가이드.md` 참조.
- 섹션 사이 수직 간격은 기본 **20px**.

## 3. 화면 흐름 (시퀀스)

```text
로딩 완료 → 대기(Idle) → 베팅 입력 → BET(시작 입력) → 진행/연출
        → 결과 표시 → 정산 완료 → 재시작 가능(CTA 복귀) → (대기)
```

- **로딩 완료:** 짧게 끝내고 즉시 조작 가능 상태를 보여준다.
- **대기(Idle):** 콘셉트 분위기 유지. idle 연출은 CTA보다 강하면 안 된다.
- **BET 입력 후:** 딜레이 없이 메인 시퀀스로 이어진다.
- **결과:** 결과 숫자와 CTA 복귀가 가장 잘 보여야 한다.
- **재시작:** 다음 행동을 막지 않는다.

초기 진입(공통 정책): `다운로드(로고+로딩 바) → 타이틀 화면 → 튜토리얼 팝업(아무 곳 터치 시 닫힘·베팅 가능)`.

## 4. 핵심 컴포넌트별 UX 규칙

### 4.1 상단 헤더
- 좌표 `x:20, y:20`, 크기 `1040 × 50`.
- 게임명(좌측) + 메뉴 버튼(우측 `50 × 50`, 햄버거 선 약 `40 × 4`).

### 4.2 히스토리(상단 pill)
- 최근 결과를 알약(pill) 뱃지로 나열(예: 최근 8건).
- 승리 = 강조색(성공), 패배 = 다크 그레이/실패색.
- 항목 간격은 일정하게, 화면 폭을 넘는 이전 기록은 **좌측에서 클리핑**한다.

### 4.3 중앙 결과 표시
- 큰 결과 숫자는 화면 중앙 정렬. **숫자/구분자 폭이 변해도 중심점은 이동하지 않는다.**
- 멀티(N≥2) 게임은 `성공 수 / 목표(k*)` 카운터를 함께 표시(실시간 갱신), N=1은 카운터 숨기고 단일 결과를 큰 숫자로.
- 진행 중에 프로핏/총 당첨금을 상시 표기하지 않는다(최고 배율 정도만 보조 표기, 최종은 결과 팝업).

### 4.4 PlayArea (게임별 핵심)
- 게임의 핵심 플레이 오브젝트(공·주사위·로켓·타일·카드 등)가 **항상 최우선 시각 대상**이다.
- 정보(성공/실패 영역, 기준선)가 입력 패널보다 **먼저 읽혀야** 한다.
- 결과 표시 영역과 상단/하단 UI가 겹치지 않게 배치한다.

### 4.5 필드/입력
- 배경은 canvas 색, 테두리 `2px`(inset stroke), 높이 `80px`, 좌우 inset `14px`.
- 2분할 입력(예: 배율 ↔ 승률)은 공식으로 **실시간 양방향 연동**한다.

### 4.6 프리셋 버튼
- Default: 어두운 raised 배경 + muted 텍스트.
- Selected: **accent 2px 테두리 + accent(또는 흰색) 텍스트** (별도 selected fill 색을 쓰지 않고 fill alpha만 낮추는 패턴 권장).
- Disabled: disabled 텍스트, 글로우 없음.

### 4.7 슬라이더
- 트랙 `16px`, 활성 fill 은 accent 계열, thumb 는 원형 또는 pause 형(테마별).
- 값 버블 + 눈금 표기. 게임 진행 중 잠글 수 있으나 **잠금 상태에서도 현재 값은 읽을 수 있어야** 한다.
- 로그 스케일이 필요한 값(예: 목표 배율)은 슬라이더는 로그, 직접 입력은 전체 범위로.

### 4.8 Turbo 토글
- 순차 연출을 생략하고 즉시(일제) 진행. 토글 `92 × 43`.
- 전용 강조색을 쓰는 테마는 그 색을 Turbo 외 요소에 쓰지 않는다.

### 4.9 Primary CTA (BET)
- 풀와이드 `1040 × 110`, radius 20, 그림자·글로우 없음.
- 눌림 상태는 최대 1~2% 스케일 축소만 허용. Hover 는 밝기 변화만.
- 오토 진행 중에는 **STOP(카운터)** 으로 전환.

### 4.10 결과 팝업
- 표시: 제목(WIN/MISSED 등), 성공 개수, 순수익(±), 총 당첨금, 최고 배율.
- 노출 정책 예시(멀티 게임 N 기준):
  - `N ≥ 10`: 완료 화면 최대 2초(탭 시 즉시) → 팝업 → 최대 3초 후 자동 닫힘
  - `N = 3~9`: 결과 팝업 즉시 → 최대 3초 후 자동 닫힘
  - `N = 1~2`: 결과 팝업 없이 완료 화면만 잠깐 유지
- 자동 닫힘 시간 이내 화면 아무 곳이나 탭하면 즉시 닫고 다음 라운드 대기.

## 5. 상태와 상호작용

| 상태 | 표현 |
| --- | --- |
| Default | 어두운 surface + muted 텍스트 |
| Hover | 테두리 명도만 소폭 증가 (또는 brightness 1.3 필터) |
| Selected | accent 2px + accent/흰 텍스트 |
| Active | accent 계열 |
| Success | 성공색 |
| Loss | 실패색 |
| Disabled | disabled 색, 글로우 없음 |
| Focus | 최소 2px 명확한 포커스 링 |

- **최소 터치 영역: 56px.**
- 게임 진행 중 입력을 잠글 수 있으나 **레이아웃은 유지**(요소 위치 이동 금지, 값은 읽기 가능).
- **애니메이션 중 레이아웃 위치가 바뀌면 안 된다**(Hover/Press로 요소가 점프 금지).

## 6. UI 잠금 규칙 (진행/오토 중)

| UI | 상태 |
| --- | --- |
| 개수/목표값/승률/프리셋/퀵버튼/AUTO 버튼 | 비활성화 |
| 메인 버튼(진행 중 STOP) | 활성 — 언제든 중지 |
| 히스토리 버튼 | 진행 중·라운드 간 비활성(비진행 중에만 조회) |
| 오토 팝업 | 진행 시작과 함께 닫힘 |

---

## 7. 연출-UI 충돌 방지 (요약)

- CTA · 베팅 버튼 · 재시작 버튼 · 잔액 · 보상 금액 · 핵심 판정 영역을 **가리는 연출은 실패한 연출**로 본다.
- CTA 가림 0%, 결과 금액 가림 0%, 핵심 플레이 오브젝트 가림 최대 10% 이하.
- 상세 규칙과 강도는 `08_이펙트_연출강도_가이드.md` 참조.
