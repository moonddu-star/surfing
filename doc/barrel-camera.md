# 배럴 카메라 비주얼 개선

작성일: 2026-09-23. 독립 Canvas POC에 적용한 연출이다. 승인 이후 PixiBrown 템플릿·제공 아트로 전환한다.

## 방향

선택한 A안(파도 내부 카메라)에 B안의 큰 캐릭터를 결합했다. 파도를 멀리서 보는 구도를 낮은 시점의 배럴 내부로 바꾸고, 화면 오른쪽의 밝은 출구와 전경의 서퍼를 중심으로 배치했다.

- 화면을 감싸는 청록색 파도, 불규칙한 물결 반사, 포말, 출구 역광.
- 화면 폭에 맞춰 확대되는 서퍼. 래시가드·보드 레일·데크·리시·트레일을 구분했다.
- 공개된 경과 시간에 따라 카메라가 배럴 안쪽으로 접근한다.
- 크루는 출구 근처의 작은 실루엣으로 배치하고, 개인 캐시아웃에 따라 퇴장한다.
- 큰 배수와 어두운 왼쪽 배경으로 숫자 가독성을 유지한다. YOU 표시는 서퍼 위치를 따라간다.

## 상태와 피니시

| 상태 | 표현 |
| --- | --- |
| 대기 | 열린 배럴과 가까운 서퍼, 출발 카운트다운 |
| 라이딩 | 점진적인 카메라 접근, 물결 흐름·물보라 증가 |
| 에어 | 보드와 서퍼가 기울며 상승한 뒤 화면 오른쪽으로 탈출 |
| 스프레이 | 낮은 턴과 넓게 퍼지는 물보라로 탈출 |
| 배럴 탈출 | 출구 쪽으로 직진하며 멀어지는 서퍼 |
| 캐시아웃 이후 | 짧은 역광 연출 후 카메라가 관전 구도로 부드럽게 복귀 |
| 크래시 | 확정된 종료 이벤트 이후에만 물이 덮인다 |
| 다음 파도 | 피니시 시간과 크루 연출 상태 초기화, 서퍼 복귀 |

정산 엔진은 변경하지 않았다. 렌더러에 전달되는 값은 현재 phase·multiplier·bet·crew이며, 미래 크래시 배수나 크루 목표 배수를 연출에 사용하지 않는다. 캐시아웃 지급은 클릭 판정 시 확정되고 피니시 재생 시간과 무관하다.

## 접근성과 화면 대응

`prefers-reduced-motion`을 실행 중에도 반영한다. 모션 감소 시 파도·카메라·서퍼는 정지 구도를 유지하고, 탈출 모션·노출 효과·크래시 물보라를 생략한다. 게임 상태와 배수는 계속 갱신한다. 반복적인 섬광이나 화면 흔들림은 사용하지 않는다.

PC에서는 큰 스테이지와 오른쪽 조작 패널을 유지한다. 모바일은 스테이지 높이 460px, 전경 서퍼 확대, 라이딩 중 화면 하단 캐시아웃 버튼을 유지한다. 디스플레이 픽셀 비율은 최대 2로 제한한다.

## 검수

- `npm run check`: 기존 정산·경합·복원 회귀 테스트 21개 및 빌드.
- `npm run test:qa`: Chromium·Firefox·WebKit, 320/360/390/520/768/1024/1440px와 기존 게임 흐름.
- `npm run test:browser`: 참가·취소·캐시아웃·테마·피니시·기록·즉시 종료·새로고침 복원.
- `npm run test:visual`: 새벽/에어/PC, 노을/스프레이/모바일, 달빛/배럴/PC의 실제 화면 캡처. 정산 보존, 크래시, 다음 라운드 복귀, 모션 감소 시 픽셀 동일성 검사.

로컬 Chromium에서 982×580 캔버스의 draw 호출 120회를 측정했을 때 중앙값 약 0.4ms, 95백분위 약 0.5ms였다. 이는 JavaScript 그리기 명령 처리 시간이며 GPU 합성 시간이나 실제 기기 FPS를 보장하는 수치는 아니다.

GitHub Actions는 전체 검수와 연출 검수가 성공한 `dist/`만 Pages에 배포한다. 최종 PNG·Spine·실기기 성능 검수는 템플릿 전환 단계에서 수행한다.
