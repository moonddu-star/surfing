# 12. 바이브 코딩 체크리스트 · AI 프롬프트 모음 (디자이너)

개발자가 구축한 prefab/환경 위에서 디자이너가 AI로 바이브 코딩할 때 쓰는 착수/검수 체크리스트와, 복붙해서 쓰는 AI 프롬프트를 모았다.

---

## 1. 작업 시작 전 (3초 판단)

- [ ] 내가 바꾸려는 게 **값**인가 **구조**인가? (값=대체로 안전 / 구조=확인 필요·금지)
- [ ] 이 값의 정본이 **prefab marker**인가? (색·폰트·좌표는 코드가 아니라 marker)
- [ ] **노드 이름/배선/서버 계약**에 손이 가는가? (그렇다면 멈추고 개발자 확인)

> 판단 기준 전체는 `02_수정_경계_가이드.md`.

---

## 2. 작업 중 체크

### 2.1 화면/레이아웃 (→ 03, 06)
- [ ] 1080×1920, 콘텐츠 폭 1040, 외곽 여백 20 을 벗어나지 않았는가?
- [ ] 패널 간격 20, 최소 터치 56px 를 지켰는가?
- [ ] 숫자가 바뀌어도 중앙 정렬 블록의 중심이 안 흔들리는가?
- [ ] 진행 중 입력이 잠겨도 레이아웃이 유지되고 값은 읽히는가?

### 2.2 컬러/타이포 (→ 04, 05)
- [ ] 색은 prefab `PaletteMarkers` 값으로 바꿨는가? (코드 하드코딩 0)
- [ ] 폰트 크기는 `TypeMarkers` 값으로 바꿨는가?
- [ ] 테마 금지색을 섞지 않았는가? (Deep Blue ↔ Neon Mint)
- [ ] 주요 값=흰색, 라벨=muted, 비활성=disabled 규칙을 지켰는가?

### 2.3 이펙트/사운드 (→ 07, 08)
- [ ] 연출을 1~10 강도로 표기했는가?
- [ ] CTA(0%)·결과 금액(0%)·핵심 오브젝트(≤10%) 가림 규칙을 지켰는가?
- [ ] 연출 때문에 시퀀스 시간이 늘어나지 않았는가?
- [ ] 강도 7+ 사운드에 BGM ducking(65%↓)이 걸렸는가?
- [ ] 사운드 파일명이 코드 호출 이름과 1:1 인가?
- [ ] GROK(Gameplay/Readability/Overlay/Keep-length) 위반이 없는가?

### 2.4 에셋 (→ 10)
- [ ] `raw-assets/` 에서만 작업했는가?
- [ ] 파일명을 유지했는가? (변경 시 개발자 확인)
- [ ] 에셋 빌드 후 화면/사운드가 정상인가?

### 2.5 베팅/문구 (→ 09, 11)
- [ ] 슬라이더/프리셋 범위가 서버 한도 안인가?
- [ ] 통화·금액을 리터럴로 안 박고 포맷 헬퍼/현지화 키를 썼는가?
- [ ] 전 로케일(31종) 키 집합을 깨지 않았는가?

### 2.6 Figma ↔ Game 비교 (Figma MCP 사용 시)
- [ ] Figma를 디자인 기준(Source of Truth)으로 삼았는가?
- [ ] Figma에서 정한 색·폰트·좌표를 코드가 아니라 prefab marker 에 적용했는가?
- [ ] 실제 Game Preview 와 Figma의 위치·크기·간격·색·타이포가 일치하는가?
- [ ] Figma에는 있지만 게임엔 없는(또는 반대) 요소를 임의로 만들지 않았는가?
- [ ] 차이 나는 항목을 "추가 수정 / 개발자 확인"으로 분류했는가?

## 3. 작업 후 마무리

- [ ] **바꾼 것 목록**을 정리했는가?
- [ ] **개발자 확인 필요 항목**을 따로 남겼는가?

- [ ] `npx tsc --noEmit` 에러가 나지 않는가? (나면 구조를 건드린 신호일 수 있음 → 개발자)

## 4. AI 프롬프트 모음 (복붙용)

### 4.1 기본 안전 지시문 (항상 먼저)
```text
이 프로젝트는 개발자가 prefab·씬·네트워크·상태·빌드 환경을 이미 구축해 둔 상태다.
너는 그 환경 위에서 화면 연출/표시/값만 조정한다.

건드리지 마라: prefab 노드 이름, @Serialize 배선, @RegisterComponent 문자열,
src/common/·src/network/·pixibrown/, 빌드 설정, 네트워크/wire/상태 구조,
확률·배당·payload·베팅 한도, public/assets 원본.

해도 되는 것: src/game/ 연출·표시 로직, prefab marker(색·폰트 크기) 값,
이미지/사운드 교체, 문구, 연출 강도·타이밍, 슬라이더 범위.

규칙: 색·폰트·좌표는 prefab 이 정본이니 코드 하드코딩 금지.
이펙트/사운드는 1~10 강도로 표기하고 CTA·결과 금액·핵심 오브젝트를 가리지 마라.
노드 삭제/이름변경이 필요하면 실행하지 말고 "개발자 확인 필요"로 보고.
애매한 값은 임의로 만들지 말고 "확인 필요"로 남겨라.
작업 후 바꾼 것과 개발자 확인 필요 항목을 정리해라.
```

### 4.2 색 바꾸기
```text
BET 버튼 색을 (원하는 색)으로 바꾸고 싶다. 색의 정본은 prefab PaletteMarkers 이니
코드에 색을 하드코딩하지 말고 어느 marker 값을 바꿔야 하는지 알려주고,
SceneMaker/개발자 작업이 필요하면 그렇게 안내해라. 테마 금지색은 쓰지 마라.
```

### 4.3 연출 강도 조정
```text
결과 승리 연출을 조금 더 강하게 하고 싶다. 08_이펙트_연출강도_가이드 기준으로
현재 강도와 제안 강도(1~10), 지속시간, BGM ducking 을 함께 제시해라.
CTA·결과 금액·핵심 오브젝트를 가리면 안 되고, 시퀀스 시간을 늘리지 마라.
```

### 4.4 이미지 교체
```text
코인 아이콘을 새 파일로 교체한다. raw-assets/game/images/ 아래에서만 작업하고
public/assets 는 건드리지 마라. 기존 파일명을 유지하고, 이름을 바꿔야 하면 알려라.
에셋 빌드 절차도 알려줘.
```

### 4.5 사운드 연결
```text
승리 효과음을 sfx-win 으로 연결하고 볼륨/겹침 간격/ducking 을 07 가이드 기준으로 제안해라.
파일은 raw-assets/game/sound 에 둔다는 전제로, 논리 이름이 코드 호출과 1:1 인지 확인해라.
```

### 4.6 Figma MCP 로 UI 구현
```text
Figma MCP 로 지금 선택한(select) 프레임/노드의 레이아웃·색·폰트·간격을 읽어라.
그 디자인을 기존 prefab 구조 위에 반영한다. 새 노드를 임의로 만들거나 노드 이름을
바꾸지 마라(필요하면 "개발자 확인 필요"로 보고). 색·폰트·좌표는 코드에 하드코딩하지 말고
prefab marker(PaletteMarkers/TypeMarkers)에 적용해라.
작업 후 Figma와 실제 화면의 차이 목록을 정리해라.
```

### 4.7 문구 변경
```text
결과 문구를 바꾸고 싶다. 통화·금액은 리터럴로 박지 말고 포맷 헬퍼/현지화 키를 쓰고,
전 로케일 키 집합을 깨지 않게 처리 순서(키 먼저, 코드 나중)를 지켜라.
번역 대상이 아닌 등급 문구(WIN/BIG WIN 등)는 영문 고정이니 건드리지 마라.
```

## 5. 문제가 생겼을 때 (자가 진단)

| 증상 | 가능한 원인 | 조치 |
| --- | --- | --- |
| 화면 일부가 안 그려짐 | 노드 이름 변경/삭제로 배선 끊김 | 되돌리고 개발자 확인 |
| 바꾼 색/폰트가 화면에 반영 안 됨 | 코드가 아니라 marker 를 바꿔야 함 | prefab marker 값 수정 |
| 이미지가 안 뜸 | public/assets 직접 수정 / 이름 불일치 / 빌드 안 함 | raw-assets 확인 + 재빌드 |
| 사운드가 안 남 | 논리 이름 불일치 | 파일 basename 확인 |
| `tsc` 에러 | 구조/타입(개발자 영역)을 건드림 | 개발자 확인 |

## 6. 장르별 매핑 예시 (같은 뼈대, 다른 게임)

새 게임도 공통 화면 슬롯에 게임 요소만 갈아끼운다.

| 공통 슬롯 | CRASH | MINE | WHEEL |
| --- | --- | --- | --- |
| PlayArea 핵심 오브젝트 | 상승 곡선/배율 | 그리드 타일 | 회전 휠/포인터 |
| 값 입력 | 목표 배율/자동 캐시아웃 | 지뢰 수 | 세그먼트 |
| 진행 시작 | 발사·상승 | 첫 타일 오픈 | 스핀 |
| 결과 | crash point | 지뢰/생존 | 착지 세그먼트 |
| Turbo | 즉시 상승 | 즉시 전체 오픈 | 빠른 스핀 |

> 매핑 후에는 `03~09` 규칙을 그대로 적용해 세부를 채운다. 구조(prefab)는 개발자가 잡아 준다.
