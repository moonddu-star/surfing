# 07. 사운드 가이드

사운드 파일명 규약, 볼륨, 타이밍/간격, BGM ducking, 재생 진입점을 담는다. 실제 게임(Multi Dice)의 `sound/game-sound.ts` 구현을 공통 패턴으로 정리했다.

> **디자이너 관점:** 사운드 파일 교체(→ `10`)와 볼륨·타이밍·ducking 값 조정은 ✅ 안전하다. 재생 진입점(클래스) 구조 자체를 바꾸는 것은 ⚠️ 개발자 확인. §8 API 는 참고용이다.

---

## 1. 원칙

- 사운드는 **논리 이름(파일 basename)** 한 겹을 두고 매니페스트 alias 를 감춘다. 게임 코드는 alias 를 몰라도 되고, 에셋이 없으면 조용히 넘어간다(경고 1회만).
- 논리 이름은 `raw-assets/game/sound/<이름>.wav` 파일명과 **1:1**.
- **재생 진입점은 단일 클래스**(예: `GameSound`)로 모은다. 개별 UI 코드가 `@pixi/sound` 를 직접 부르지 않는다.
- 볼륨·간격 정책은 이 문서와 `08_이펙트_연출강도_가이드.md`(강도 스케일)를 함께 따른다.
- 콘셉트 일치: 같은 강도라도 테마(Halloween/Fantasy/Sci-Fi/Casino/Cute)마다 표현이 달라야 한다. 임시 사운드가 콘셉트와 안 맞으면 `확인 필요`로 남긴다.

---

## 2. 파일명(논리 이름) 규약

- kebab/snake 소문자, 역할이 드러나는 이름. 확장자는 `.wav`(우선) 또는 `.mp3`.
- resolve 는 여러 후보 경로를 순서대로 탐색한다:

```text
game/sound/<name>.wav → game/sound/<name>.mp3 → game/sound/<name>
→ <name>.wav → <name>.mp3 → <name>
```

- 공통 논리 이름 예시(새 게임도 이 역할 세트를 기준으로):

| 상수 | 논리 이름 예 | 용도 |
| --- | --- | --- |
| `UI_TAP` | `button-click` | 버튼·토글·칩 등 일반 UI 탭 |
| `INSUFFICIENT` | `insufficient-balance` | 잔액 부족 등 베팅 불가 |
| `WIN` | `sfx-win` | 라운드 승리 결과 |
| `LOSE` | `sfx-missed` | 라운드 패배 결과 |
| `BGM` | `bgm_02` | 배경음악 |
| (게임 이벤트) | 예: `target-cross` | 게임 고유 순간(기준 통과 등) |
| (게임 오브젝트 변형) | 예: `dice_shortsound_low1…high2` | 임팩트 피치 변형 세트 |

---

## 3. 볼륨 기준값

실제 구현에서 쓰는 볼륨(0~1). 새 게임의 출발점으로 사용한다.

| 사운드 | 볼륨 | 비고 |
| --- | ---: | --- |
| UI 탭 | 0.40 | |
| 슬라이더 틱(tick) | 0.35 | |
| 잔액 부족 | ~0.38 | |
| 결과(win/lose) | 0.55 | |
| 게임 이벤트(예: target-cross) | 0.50 | 동시 다발 시 피크 억제 |
| BGM | ~0.16 (0.225 × 0.7) | fade-in 0.8초 |
| 오브젝트 임팩트 | 0.1 + power×0.35 (max 0.45) × 1.15 | 세기(power)에 비례 |
| 최종 착지 임팩트 | 0.2 × 1.15 | |

- 모바일 스피커 기준으로도 찢어지거나 피로한 고역이 나지 않아야 한다.

---

## 4. 타이밍 · 겹침 방지(gap) 규칙

- **겹침 방지 간격(gap)은 "마지막 재생 시각" 기준**이지 파일 길이 기준이 아니다. 파일 뒤 무음 때문에 길이로 잡으면 연속 타격이 대부분 누락된다.
- 같은 채널(key)에 최소 간격을 준다:

| 대상 | 최소 간격(gap) |
| --- | --- |
| UI 탭 | 0.02초 |
| 잔액 부족 | 0.10초 |
| 게임 이벤트 공유 그룹(예: target-cross) | 0.03초 |
| 오브젝트 임팩트 | 0.03초 |

- 반복 이벤트는 같은 위치에서 **0.15초 이내 중복 발생 시** 합치거나 이전 소리를 약화한다.
- 미세 입력(값 변화 없음, 홀수 스텝 등)은 무음 처리해 틱 과다를 막는다.

### 4.1 대량 동시 발음 상한

핵심 오브젝트가 수십~수백 개 동시에 소리내면 뭉개지고 오디오 인스턴스가 낭비된다. **개수 구간별 상한**을 둔다(예시):

```text
1~49개   : 전부 발음
50~70개  : 최대 60개
71~100개 : 최대 80개
```

- 가장 늦게/중요하게 도착하는 대상은 반드시 들리도록 먼저 채우고, 나머지는 무작위로 채운다.
- 한 라운드 동안 각 오브젝트가 고정해서 쓰는 피치 변형을 미리 배정한다(±3% 범위 변형 세트).

## 5. BGM ducking (강도 연동)

효과음/보상 음악이 들어올 때 BGM을 낮춘다(기존 볼륨 100% 기준 목표 볼륨).

| 상황 | 사운드 강도 | BGM 목표 | Duck In | Duck Out |
| --- | ---: | ---: | ---: | ---: |
| 일반 UI 클릭 | 1~3 | 100% | 0 | 0 |
| 옵션 변경/토글 | 2~3 | 95~100% | 0~0.05 | 0.1 |
| 시퀀스 시작 | 4~5 | 80~90% | 0.05~0.1 | 0.2~0.4 |
| 일반 진행 hit | 2~4 | 90~100% | 0~0.05 | 0.1~0.2 |
| 상승 cue | 4~6 | 75~90% | 0.05~0.15 | 0.3~0.6 |
| 하락 cue | 2~4 | 90~100% | 0.05 | 0.2~0.3 |
| 피쳐 진입 | 6~7 | 65~80% | 0.1~0.2 | 0.5~0.8 |
| 일반 win | 4~5 | 80~90% | 0.05~0.15 | 0.4~0.7 |
| Big Win | 7 | 50~65% | 0.15~0.3 | 0.8~1.5 |
| Mega/Epic Win | 8~9 | 35~50% | 0.2~0.4 | 1.0~2.0 |
| Max Win/Jackpot | 10 | 20~35% | 0.2~0.5 | 1.5~3.0 |
| 정산 완료/복귀 | 3~4 | 90~100% | 0.05 | 0.3~0.6 |

- 강도 7 이상 사운드가 들어갈 때는 BGM을 65% 이하로, 9~10에서는 20~50%까지 낮춘다.
- 같은 주파수 대역의 impact/bass/fanfare 를 동시에 쌓지 않는다.

---

## 6. 상승 / 하락 / 시작 / 종료 사운드

**상승:** 보상·배수·레벨 증가에. pitch 는 단계당 3~8% 상승. 3단계 이상 연속 시 새 효과음을 크게 반복하지 말고 layer 추가 또는 pitch만 조정. 강도 6 이상이면 BGM 75~85%. Big Win 으로 이어지면 마지막 0.2~0.4초를 impact 와 겹친다.

**하락:** 실패·감소·미스. 벌주는 느낌보다 짧게 인지. 강도 2~4 초과 금지. BGM 90~100% 유지. 하락 사운드로 다음 CTA 복귀가 늦어지면 안 된다.

**시퀀스 시작:** 기본 강도 4~5. 시작 위치/핵심 오브젝트/카메라 이동 중 하나와 동기화. 시작음 이후 0.3초 안에 실제 움직임이 보여야 한다. 강도 5 이상이면 BGM 80~90%.

**시퀀스 종료:** 기본 강도 3~4. 결과 표시 또는 CTA 복귀와 동기화. 종료음 위해 별도 대기 시간 만들지 않음. 종료 후 0.2~0.5초 안에 입력 가능 상태 표시.

---

## 7. BGM 재생 · 음소거

- BGM은 게임 진입 시 **한 번만** 시작한다. 자동재생이 막힌 브라우저는 첫 입력 후 울린다.
- 전역 음소거는 단일 함수로만(메뉴 토글·저장된 설정이 이 함수로 들어온다): global/effect/voice/bgm 채널을 함께 mute.
- 라운드가 끊길 때 남은 소리를 정리(`stopAll`)하고 BGM 시작 플래그를 리셋한다.

## 8. 재생 진입점 API 패턴 (권장 시그니처)

```ts
class GameSound {
  static playTap(): void;                         // UI 탭
  static playCountTick(prev, next): void;         // 개수 슬라이더 틱(값 변화 시만)
  static playValueTick(prev, next): void;         // 값 슬라이더 틱(|Δ|≥임계)
  static playInsufficient(): void;                // 잔액 부족
  static playResult(won: boolean): void;          // 결과 확정
  static startBgm(): void;                         // 1회 시작
  static setMuted(muted: boolean): void;          // 전역 음소거
  static stopAll(): void;                          // 정리
  // 게임 이벤트/오브젝트는 게임별로 추가
}
```

- 내부는 `resolve(name)` → 존재 확인 → `createEffect(key, volume, ..., channelKey, gap)` 흐름.
- 못 찾은 결과는 캐시하지 않아 번들이 늦게 로드돼도 다음 호출에 붙는다.

## 9. 사운드 검수 체크리스트

- [ ] 사운드 강도가 1~10으로 표기되어 있는가?
- [ ] 강한 사운드(7+) 시 BGM ducking 퍼센트가 지정되어 있는가?
- [ ] 상승/하락/시작/종료 사운드가 시퀀스 의미와 맞는가?
- [ ] 겹침 방지 gap 이 파일 길이가 아니라 마지막 재생 시각 기준인가?
- [ ] 대량 동시 발음 상한이 걸려 있는가?
- [ ] 사운드가 디자인 콘셉트와 맞는가? (임시 사운드는 확인 필요로)
- [ ] 반복 플레이 시 피로하지 않은가?
- [ ] 모바일 작은 스피커에서 가독성·음량 균형이 유지되는가?
