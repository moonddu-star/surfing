# 서핑 개발 기준 및 POC 현황

작성일: 2026-09-22.

## 사용자 지시

템플릿은 아직 승인 전이므로, 우선 [surfing 저장소](https://github.com/moonddu-star/surfing)에 독립 POC를 구성한다. `doc/skills`와 `doc/design`은 현재 참고 자료로 활용하며, POC를 완료한 뒤 템플릿·가이드 구조로 전환한다.

이 지시는 초기의 “템플릿·이미지 수령 대기” 상태를 대체한다. 현재 POC 단계에서는 HTML/CSS UI와 절차적 Canvas 연출을 사용한다. 최종 프로젝트에서의 prefab·에셋 규칙을 폐기한 것은 아니다.

## POC 시연값

아래 값은 사용자가 최종 승인한 상용 사양이 아닌, POC를 실행하기 위한 임시 설정이다.

| 항목 | 값 |
| --- | --- |
| 시작 잔액 | 1,000 CR |
| 참가 금액 | 1–100 CR, 소수점 둘째 자리까지 |
| 기본 참가 금액 | 10 CR |
| 대기 시간 | 8초 |
| 종료 표시 | 4.2초 |
| 배수 상승 | `exp(0.105 × 경과초)` |
| 일반 크래시 | `min(50, max(1, floor(0.99 / (1-u) × 100) / 100))` |
| 배수 표시·지급 | 배수 소수점 둘째 자리 절삭, 참가 금액과 곱한 지급액도 소수점 둘째 자리 절삭 |
| 판정 경합 | 로컬 엔진 시간을 먼저 진행. 크래시 시점과 같거나 늦은 캐시아웃은 미승인 |
| 상한 50배 | POC에서는 크래시로 종료. 최종 지급 한도 정책과 별개 |
| 새로고침 | 미정산 참가금 복원. 승인된 캐시아웃은 재지급하지 않음 |

일반 분포의 0.99 계수는 상용 RTP를 보증하지 않는다. 실제 결과 분포·표시·정산·한도·공정성은 최종 수학 및 서버 사양으로 다시 확정한다. POC 시나리오는 현재 미참가 대기 라운드 또는 다음 라운드에만 적용하고, 참가가 완료된 파도의 결과를 바꾸지 않는다.

## 참고 문서 적용

- [서핑 기획](../SURFING_GAME_DESIGN.md): 게임 콘셉트와 POC의 검증 목적.
- [제작 파이프라인](skills/SKILL.md): 템플릿 확보 이후 적용할 최종 제작 기준.
- [공통 디자인 가이드](design/00_공통가이드_인덱스.md): 정보 구분, 숫자 정렬, 조작 상태, 연출 가림 방지 등을 참고.
- [PixiBrown 전환 계획](pixibrown-migration.md): 현재 모듈과 최종 prefab·컴포넌트·서버 책임 매핑.

Massive Mines·Avi-Cluck의 RTP, 구좌 수, 사이드 베팅, 오토 UI 등은 서핑에 복사하지 않는다. 원본 참고 문서와 기존 기획서 파일명은 보존한다.

## 후속 범위

- 템플릿 수령 후 SceneMaker prefab·엔진 컴포넌트·에셋 파이프라인 전환.
- 제공 레이아웃·PNG·Spine·사운드로 POC 표현 교체.
- 실제 공통 라운드 서버 및 캐시아웃·재접속 계약 연동.
- 최종 수학·RTP·지급 한도·정밀도 검증.
- 친구 계정 비교, 라이딩 리플레이·클립 저장 등 후속 기능.

실행 명령과 테스트 방법은 [루트 안내](../readme.md)를 따른다.
