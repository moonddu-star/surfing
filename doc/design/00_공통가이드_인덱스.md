# Massive Series 공통 제작 가이드 (디자이너 바이브 코딩용)

`01`–`13`은 Massive Series 저장소(예: Multi Dice, Multi Limbo)를 분석해 정리한 **게임 공통 제작 가이드**다.
특정 게임(DICE, LIMBO)에만 해당하는 규칙이 아니라, **같은 프레임워크로 다른 장르를 바로 만들 수 있도록** 공통 분모만 뽑아 카테고리별로 분리했다.

> Massive Mines 작업이라면 **먼저 `Massive_Mines_GDD.md`** 를 읽는다. 아래 `README_디자이너.md` / `디자이너_제작_가이드.md` 는 이 저장소에 아직 없다.

---

## 이 가이드의 전제 — 작업 분담 구조

```text
[ 개발자 ]  프리팹(prefab) · 씬 · 네트워크 · 상태 · 빌드 환경을 미리 구축한다.
                    │
                    ▼   (구축된 환경 위에서)
[ 디자이너 ]  Figma → Figma MCP → AI 바이브 코딩 → Game
              화면·연출·색·크기·사운드·문구를 채운다.
```

기준(Source of Truth)은 3층으로 나뉜다. 혼동하면 값을 코드에 하드코딩하는 사고가 난다.

- **Figma** = "어떻게 보여야 하는가"(디자인 의도의 기준)
- **Prefab / marker** = "그 값이 실제로 들어가는 자리"(게임 구조·값의 정본)
- **MD 가이드** = "무엇을/어떻게 해도 되는가"(제작 규칙의 기준)

> Figma에서 정한 색·폰트·좌표 값은 **코드가 아니라 Prefab marker(또는 SceneMaker/개발자)** 에 적용한다.

- **개발자 영역:** prefab 노드 구조, `@Serialize` 배선, 네트워크/서버 어댑터, 상태 관리, 빌드 설정. → 디자이너는 **건드리지 않는다.**
- **디자이너 영역:** prefab 이 이미 만들어 둔 화면 위에서 **보이는 것과 느껴지는 것**(레이아웃 값, 색, 폰트 크기, 이미지, 연출 강도/타이밍, 사운드, 문구, 베팅 UX 값)을 조정한다.
- 그래서 이 가이드의 핵심은 "만드는 법"이 아니라 **"무엇을 안전하게 바꿀 수 있고, 무엇을 건드리면 안 되는가"** 다.

> 가장 먼저 `02_수정_경계_가이드.md` 를 읽는다. 이 문서 하나가 사고를 막는다.

## AI 바이브 코딩 표준 지시문 (복붙용)

새 작업을 AI에게 맡길 때 이 문장을 먼저 붙인다.

```text
이 프로젝트는 Massive Mines다. 제품 규칙의 정본은 doc/Massive_Mines_GDD.md 이다.
공통 가이드(01–13)와 충돌하면 GDD를 따른다.

개발자가 prefab·씬·네트워크·상태·빌드 환경을 이미 구축해 둔 상태라면,
너는 그 환경 위에서 화면 연출/표시/값만 조정한다. 다음을 반드시 지켜라.

[건드리지 마라]
- prefab 노드 이름, @Serialize 배선, @RegisterComponent 문자열
- src/common/, src/network/, pixibrown/ 내부 코드
- 네트워크/서버 어댑터/wire 포맷, 상태 관리 구조, 빌드 설정(vite/tsconfig/terser)
- 확률·배당·payload·베팅 한도 등 서버 계약 값

[해도 되는 것]
- src/game/ 안의 연출/표시 로직 조정
- prefab marker(색·폰트 크기) 값, 이미지/사운드 교체, 문구, 연출 강도·타이밍, 슬라이더 범위

[규칙]
- Figma MCP가 연결돼 있으면 Figma를 디자인 기준(Source of Truth)으로 삼아라.
- 단, Figma에서 정한 색·폰트·좌표 값은 코드에 하드코딩하지 말고 prefab marker 에 적용해라.
- 이펙트/사운드는 1~10 강도로 표기하고 CTA·결과 금액·핵심 오브젝트를 가리지 마라.
- 애매하면 임의로 정하지 말고 "확인 필요"로 남겨라.
- 작업 후: 바꾼 것 / Figma와 비교 결과 / 개발자 확인이 필요한 항목을 정리해라.
```
